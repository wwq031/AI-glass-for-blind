# 自有双端应用完整导航任务实机闭环设计

## 状态与验收范围

本设计以用户确认的第一轮实机目标为准：运行我们自己的手机应用和眼镜端应用，由盲人用户无屏完成“语音说目的地 → 语音确认候选 → 真实定位及步行导航 → 沿途关键提醒与到达提醒 → 按眼镜实体键确认观察入口 → 真实拍摄、识别、播报入口信息”。到达并完成入口确认是本轮终点；菜单阅读和可见表情辅助属于后续任务。手机屏幕仅用于安装、授权和故障排查。

当前设备已通过 ADB 分别识别为荣耀 `BVL-AN16`（Android 16）和 Rokid `RG_glasses`（Android 12）。GitHub 现有高德 Web 服务 API 适配器，已经实现地点搜索与步行路线计算；设备无关的 `SessionOrchestrator`、Skill/Tool 合同、语音输入接口、导航提醒策略和模拟设备传输也已存在。现有演示仍使用假定位、假 ASR 和录制或模拟结果；仓库尚无可安装的自有 Android 手机工程、眼镜端 JSUI 应用及连续定位导航运行时。代码完成与离线测试通过都不构成实机验收。

本文件结合既有文档与用户最新确认的实施路径：眼镜通过蓝牙/CXR 连接我们的手机应用；眼镜转交按键、录音和拍摄结果，手机协调定位、导航、模型语音识别、视觉识别、Agent 推理及模型语音合成，再把结果送回眼镜。旧文档的双端独立联网、云端共享 `session_id` 是备选思路，不是本次实验的主链路。眼镜无需独立连接 Wi-Fi；不默认用 Android 系统 SpeechRecognizer 或系统 TTS 代替模型服务。

## 实机能力与未证实边界

### 2026-09-29 晚间设备实验补记

自有 CXR-M 应用在缺少 Rokid 授权材料时返回 `SN_CHECK_FAILED`。CXR-L 探针经 Rokid AI App 授权成功，但数据服务未回调，不能算业务链路。为赶上实机实验，已安装自有 Android 手机和眼镜 RFCOMM 应用，不依赖独立眼镜 Wi-Fi 或 CXR-M 授权。双向会话消息、眼镜实体键到手机、手机真机定位事件到眼镜、实体键授权拍摄并传完整 JPEG、实体键授权录音并传完整 WAV 均在两台设备上通过。手机到眼镜发送约 2 秒测试音频后，眼镜音轨记录播放完成，佩戴者确认听到声音。后文涉及“首轮 CXR”的段落是原定方案，完整验收可以改用已实测的自有蓝牙通道，但必须补齐真实模型、连续导航和业务任务。实测详情见 `apps/device-experiment/android/README.md`。

## 方案选择

采用自有 Android 手机 APK、自有 Rokid JSUI 眼镜应用和现有 `DeviceTransport` 接缝。眼镜负责实体键、录音、按授权拍摄及音频播报；手机作为任务运行与外部服务调用中心，负责定位、连续步行导航事件、模型 ASR/TTS、视觉识别和 Agent 推理的调用与回放。若模型服务需要网关保护凭据，该网关由手机调用，眼镜只经 CXR 与手机通信。`PhoneAgentRuntime` 调用现有 Agent 核心，外部 Event、Plan、ToolResult、Effect 保持可追踪并显式回放。模型只提出受合同约束的 Plan，不能直接启动导航、拍摄或发布通行结论。

首轮使用眼镜—手机的蓝牙/CXR 连接。手机端 CXR 适配器与眼镜端适配器交换带 `session_id + sequence` 的事件、命令与媒体引用；底层是否为蓝牙数据或 SDK 协商的其他媒体链路，以所用 SDK 的实测行为为准，不要求眼镜单独联网。须用我们自己签名安装的应用验证连接、鉴权与权限，不能以官方 Rokid 应用的界面或业务进程代替。ADB 转发仅可用于定位问题，不能计作独立安装验收。

## 连续任务流程

1. 眼镜实体键唤起录音；音频经 CXR 送到手机，由手机调用所选模型 ASR，最终识别文本归一为 `SpeechInput`。低置信度或无结果请求重说，不启动导航。
2. Agent 根据语音目标和注册 Skill 形成受验证的 Plan；地点服务结合手机真实定位搜索候选。候选经眼镜语音播报，用户用语音确认明确的地点及坐标。没有坐标或确认时不开始路线。
3. 手机导航适配器获取真实步行路线并开始连续定位。路线进度装配器将转向临近、偏航、重规划、定位质量下降、路口临近、到达和停止归一为带 `session_id + sequence` 的导航 Event。定位无效时不得把旧位置当作当前事实。
4. 导航提醒由策略输出并经语音优先级调度播报。路口临近只建立上下文和发出可检查提醒，不自动拍摄；若用户明确请求路口观察，沿用已有独立确认、事实回放和保守建议边界，不把观察结果说成安全通行保证。
5. 到达目标附近时播报到达和入口观察提示。用户按眼镜实体键才授予这一次入口拍摄；眼镜在本地核对触发时效后拍摄，经 CXR 送到手机并与 `session_id` 对齐。图片以 `MediaTransfer` 引用传递，不进入 Agent 上下文或日志正文。
6. 入口观察 Provider 返回结构化事实、置信度和限制。`ToolResult` 显式回放到 Agent 核心；所选模型 TTS 生成播报音频，眼镜播放可见入口线索及不确定性。低置信度、拍摄失败或超时请用户调整方向并重拍，不伪造入口位置。

任一步可由用户取消；断连、位置弱、地图失败、模型失败、拍摄失败和播报失败产生明确事件及短语音降级。紧急提示可打断普通导航详情。手机在本地记录事件序号、调用状态及错误原因，重连后先对账，避免重复导航或重复拍摄。

## 模块接缝与配置

- `apps/phone-companion` 增加可安装 Android 入口、前台导航服务及权限处理；复用已有高德 Web API 地点/路线适配器，增加实时定位和连续导航事件适配层。Android、地图及传输类型不进入 `packages/domain`。
- `apps/glasses-agent` 增加 JSUI 应用入口、按键去抖、录音、受控摄像和模型 TTS 音频播放；不持有导航或长期任务状态。
- `packages/providers/device/DeviceTransport` 仍是双端业务接缝，首轮实现真实 CXR 适配器；模拟器继续服务离线回放。模型网关如需使用，只在手机到模型服务的链路中出现。
- 地图和模型凭据通过本机开发配置或安装时配置注入，不提交到 Git。当前工作区未配置高德凭据；真机验收必须使用真实地点、真实位置、真实路线、真实观察结果和真实播报。录制模型与假定位只用于回归测试。

## 分阶段验证与完成定义

1. **设备能力关口**：自有测试包在眼镜和手机上可安装、可启动；经 CXR 完成眼镜按键、录音、拍摄媒体到手机，以及模型 ASR、模型 TTS 音频返回眼镜的往返，并记录失败原因。
2. **导航关口**：自有手机应用复用已有地点搜索/路线计算能力，以真实位置开始连续步行导航，沿途产生转向、偏航或定位弱等规范事件，最终到达；无手机选点步骤。
3. **整体关口**：从语音目标到用户按键观察入口在同一任务会话内完成；导航提醒不自动拍摄；失败、取消、断连和重试均可语音理解且不会重复外部动作。保存脱敏的 `session_id + sequence` 事件记录、设备/应用版本和实机结果。

只有第三关在两台设备上使用我们自己的应用实际通过，才称“完整导航任务实机闭环已完成”。合同测试、模拟回放、APK 构建成功、安装成功以及官方应用能运行，分别只证明各自那一步。
