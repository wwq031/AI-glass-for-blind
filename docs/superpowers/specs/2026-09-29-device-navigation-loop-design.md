# 自有双端应用完整导航任务实机闭环设计

## 状态与验收范围

本设计以用户确认的第一轮实机目标为准：运行我们自己的手机应用和眼镜端应用，由盲人用户无屏完成“语音说目的地 → 语音确认候选 → 真实定位及步行导航 → 沿途关键提醒与到达提醒 → 按眼镜实体键确认观察入口 → 真实拍摄、识别、播报入口信息”。到达并完成入口确认是本轮终点；菜单阅读和可见表情辅助属于后续任务。手机屏幕仅用于安装、授权和故障排查。

当前设备已通过 ADB 分别识别为荣耀 `BVL-AN16`（Android 16）和 Rokid `RG_glasses`（Android 12）。仓库已有设备无关的 `SessionOrchestrator`、Skill/Tool 合同、录制的 Agent 和路口回放；没有可安装的 Android 手机工程、眼镜端 JSUI 应用、真实 CXR 适配器或端侧导航运行时。现有高德适配器只提供地点搜索与一次步行路线计算，不提供连续定位、路线进度或转向事件。设备接通和离线测试通过都不构成本设计的实机验收。

## 方案选择

采用自有 Android 手机 APK、自有 Rokid JSUI 眼镜应用和现有 `DeviceTransport` 接缝。手机负责会话、语音、定位、步行导航、模型规划、事实提供者和播报调度；眼镜负责实体键、按授权拍摄、媒体传输与播报终端。`PhoneAgentRuntime` 调用现有 Agent 核心，外部 Event、Plan、ToolResult、Effect 保持可追踪并显式回放。模型只提出受合同约束的 Plan，不能直接启动导航、拍摄或发布通行结论。

手机与眼镜通信先验证 `RokidCxrAdapter` 能否作为普通第三方应用建立连接、接收按键、请求拍摄、传回图片和播放语音。眼镜系统中的 `com.rokid.cxrservice.CXRService` 声明为 exported；这只证明组件可寻址，不证明第三方鉴权、协议或媒体权限可用。验证须由我们自己签名安装的探针完成，不以官方 Rokid 应用的界面或业务进程代替。若普通应用无法通过 CXR 获取所需能力，该关口必须报告为未通过，重新评审设备传输方案；ADB 转发仅可用于定位问题，不能计作独立安装验收。

## 连续任务流程

1. 眼镜实体键唤起手机的语音输入。Android 语音适配器将最终识别结果归一为 `SpeechInput`，低置信度或无结果请求重说，不启动导航。
2. Agent 根据语音目标和注册 Skill 形成受验证的 Plan；地点服务结合手机真实定位搜索候选。候选经眼镜语音播报，用户用语音确认明确的地点及坐标。没有坐标或确认时不开始路线。
3. 手机导航适配器获取真实步行路线并开始连续定位。路线进度装配器将转向临近、偏航、重规划、定位质量下降、路口临近、到达和停止归一为带 `session_id + sequence` 的导航 Event。定位无效时不得把旧位置当作当前事实。
4. 导航提醒由策略输出并经语音优先级调度播报。路口临近只建立上下文和发出可检查提醒，不自动拍摄；若用户明确请求路口观察，沿用已有独立确认、事实回放和保守建议边界，不把观察结果说成安全通行保证。
5. 到达目标附近时播报到达和入口观察提示。用户按眼镜实体键才授予这一次入口拍摄；手机验证会话、请求时效与授权后，经 `DeviceTransport` 请求眼镜拍摄。图片以 `MediaTransfer` 引用传递，不进入 Agent 上下文或日志正文。
6. 入口观察 Provider 返回结构化事实、置信度和限制。`ToolResult` 由手机运行时显式回放到 Agent 核心；播报描述可见入口线索及不确定性。低置信度、拍摄失败或超时请用户调整方向并重拍，不伪造入口位置。

任一步可由用户取消；断连、位置弱、地图失败、模型失败、拍摄失败和播报失败产生明确事件及短语音降级。紧急提示可打断普通导航详情。手机在本地记录事件序号、调用状态及错误原因，重连后先对账，避免重复导航或重复拍摄。

## 模块接缝与配置

- `apps/phone-companion` 增加可安装 Android 入口、前台导航服务及权限处理；通过适配层调用设备无关的 Agent 核心。Android、地图、语音和 CXR 类型不进入 `packages/domain`。
- `apps/glasses-agent` 增加 JSUI 应用入口、按键去抖、受控摄像和播报桥；不持有导航或长期任务状态。
- `packages/providers/device/DeviceTransport` 仍是唯一手机—眼镜业务接缝。真实 CXR 探针通过后再实现正式适配器，模拟器继续服务离线回放。
- 地图和模型凭据通过本机开发配置或安装时配置注入，不提交到 Git。当前工作区未配置高德凭据；真机验收必须使用真实地点、真实位置、真实路线、真实观察结果和真实播报。录制模型与假定位只用于回归测试。

## 分阶段验证与完成定义

1. **设备能力关口**：自有测试包在眼镜和手机上可安装、可启动；第三方 CXR 通道完成按键、拍摄媒体和播报往返，并记录成功或具体拒绝原因。
2. **导航关口**：自有手机应用用语音选择真实目的地，利用真实位置开始步行导航，沿途产生转向、偏航或定位弱等规范事件，最终到达；无手机选点步骤。
3. **整体关口**：从语音目标到用户按键观察入口在同一任务会话内完成；导航提醒不自动拍摄；失败、取消、断连和重试均可语音理解且不会重复外部动作。保存脱敏的 `session_id + sequence` 事件记录、设备/应用版本和实机结果。

只有第三关在两台设备上使用我们自己的应用实际通过，才称“完整导航任务实机闭环已完成”。合同测试、模拟回放、APK 构建成功、安装成功以及官方应用能运行，分别只证明各自那一步。
