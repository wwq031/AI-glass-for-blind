# 自有双端应用完整导航任务实机闭环设计

## 状态与验收范围

本设计以用户确认的第一轮实机目标为准：运行我们自己的手机应用和眼镜端应用，由盲人用户无屏完成“语音说目的地 → 语音确认候选 → 真实定位及步行导航 → 沿途关键提醒与到达提醒 → 按眼镜实体键确认观察入口 → 真实拍摄、识别、播报入口信息”。到达并完成入口确认是本轮终点；菜单阅读和可见表情辅助属于后续任务。手机屏幕仅用于安装、授权和故障排查。

当前设备已通过 ADB 分别识别为荣耀 `BVL-AN16`（Android 16）和 Rokid `RG_glasses`（Android 12）。GitHub 现有高德 Web 服务 API 适配器，已经实现地点搜索与步行路线计算；设备无关的 `SessionOrchestrator`、Skill/Tool 合同、语音输入接口、导航提醒策略和模拟设备传输也已存在。现有演示仍使用假定位、假 ASR 和录制或模拟结果；仓库尚无可安装的自有 Android 手机工程、眼镜端 JSUI 应用及连续定位导航运行时。代码完成与离线测试通过都不构成实机验收。

本文件续接 `docs/superpowers/specs/2026-07-25-rokid-coze-assistive-agent-design.md` 和中期检查文档的双端架构。用户要求采用模型语音识别、模型语音合成和真实视觉模型。手机负责定位导航事实及会话协同，可以承载网络转发，但不默认使用 Android 系统 SpeechRecognizer 或系统 TTS 代替模型服务。

## 方案选择

采用自有 Android 手机 APK、自有 Rokid JSUI 眼镜应用和现有 `DeviceTransport` 接缝。手机负责定位、连续步行导航事件和会话协同；眼镜负责实体键、录音、按授权拍摄、媒体上传与音频播报；所选模型服务负责 ASR、TTS、视觉识别和 Agent 推理，项目网关负责鉴权、会话对齐、服务调用和结果分发。`PhoneAgentRuntime` 调用现有 Agent 核心，外部 Event、Plan、ToolResult、Effect 保持可追踪并显式回放。模型只提出受合同约束的 Plan，不能直接启动导航、拍摄或发布通行结论。

首轮按既有文档的路线，手机上传结构化导航事件，眼镜上传按键与图像；两端在项目网关通过同一个 `session_id` 对齐状态，并通过 WebSocket 或短轮询收取消息。`DeviceTransport` 可提供这一实现；CXR 直连是后续可替换传输。若选择 CXR，须用我们自己签名安装的应用验证协议与权限，不能以官方 Rokid 应用的界面或业务进程代替。ADB 转发仅可用于定位问题，不能计作独立安装验收。

## 连续任务流程

1. 眼镜实体键唤起录音；音频经项目网关送至所选模型 ASR，最终识别文本归一为 `SpeechInput`。低置信度或无结果请求重说，不启动导航。
2. Agent 根据语音目标和注册 Skill 形成受验证的 Plan；地点服务结合手机真实定位搜索候选。候选经眼镜语音播报，用户用语音确认明确的地点及坐标。没有坐标或确认时不开始路线。
3. 手机导航适配器获取真实步行路线并开始连续定位。路线进度装配器将转向临近、偏航、重规划、定位质量下降、路口临近、到达和停止归一为带 `session_id + sequence` 的导航 Event。定位无效时不得把旧位置当作当前事实。
4. 导航提醒由策略输出并经语音优先级调度播报。路口临近只建立上下文和发出可检查提醒，不自动拍摄；若用户明确请求路口观察，沿用已有独立确认、事实回放和保守建议边界，不把观察结果说成安全通行保证。
5. 到达目标附近时播报到达和入口观察提示。用户按眼镜实体键才授予这一次入口拍摄；眼镜在本地核对触发时效后拍摄，经项目网关把图片与 `session_id` 对齐。图片以 `MediaTransfer` 引用传递，不进入 Agent 上下文或日志正文。
6. 入口观察 Provider 返回结构化事实、置信度和限制。`ToolResult` 显式回放到 Agent 核心；所选模型 TTS 生成播报音频，眼镜播放可见入口线索及不确定性。低置信度、拍摄失败或超时请用户调整方向并重拍，不伪造入口位置。

任一步可由用户取消；断连、位置弱、地图失败、模型失败、拍摄失败和播报失败产生明确事件及短语音降级。紧急提示可打断普通导航详情。手机在本地记录事件序号、调用状态及错误原因，重连后先对账，避免重复导航或重复拍摄。

## 模块接缝与配置

- `apps/phone-companion` 增加可安装 Android 入口、前台导航服务及权限处理；复用已有高德 Web API 地点/路线适配器，增加实时定位和连续导航事件适配层。Android、地图及传输类型不进入 `packages/domain`。
- `apps/glasses-agent` 增加 JSUI 应用入口、按键去抖、录音、受控摄像和模型 TTS 音频播放；不持有导航或长期任务状态。
- `packages/providers/device/DeviceTransport` 仍是双端业务接缝，首轮经项目网关按 `session_id` 中转；真实 CXR 适配器可在独立实测后加入，模拟器继续服务离线回放。
- 地图和模型凭据通过本机开发配置或安装时配置注入，不提交到 Git。当前工作区未配置高德凭据；真机验收必须使用真实地点、真实位置、真实路线、真实观察结果和真实播报。录制模型与假定位只用于回归测试。

## 分阶段验证与完成定义

1. **设备能力关口**：自有测试包在眼镜和手机上可安装、可启动；经项目网关完成眼镜录音、模型 ASR、模型 TTS 播报、按键、拍摄媒体往返，并记录失败原因。
2. **导航关口**：自有手机应用复用已有地点搜索/路线计算能力，以真实位置开始连续步行导航，沿途产生转向、偏航或定位弱等规范事件，最终到达；无手机选点步骤。
3. **整体关口**：从语音目标到用户按键观察入口在同一任务会话内完成；导航提醒不自动拍摄；失败、取消、断连和重试均可语音理解且不会重复外部动作。保存脱敏的 `session_id + sequence` 事件记录、设备/应用版本和实机结果。

只有第三关在两台设备上使用我们自己的应用实际通过，才称“完整导航任务实机闭环已完成”。合同测试、模拟回放、APK 构建成功、安装成功以及官方应用能运行，分别只证明各自那一步。
