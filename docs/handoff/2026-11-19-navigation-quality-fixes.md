# 2026-11-19 导航、图片与快捷输入修复

基线为 GitHub `main@8dd967d`，本地分支 `fix/agent-navigation-quality-20261119`。本轮没有推送、安装设备、生成完整模型 APK 或调用付费模型。

## 已实现

- 地点搜索保留最多 20 个有效候选再去重、排序、截取 3 个。名称匹配优先，裸地名在同等匹配程度下优先公共交通节点和地标，最后比较距离；明确酒店等目标时尊重具体名称。地址、可用距离、可读类别传入 Agent。排序只作用于供应商实际返回的候选，不保证某个 POI 一定被召回。
- OCR/读字请求 `1920×1080 / quality 95`，普通场景 `1280×720 / quality 90`。使用统一 PhotoDecoder 校验完整文件、12 MB 上限、4096 边长及 1200 万像素上限。有效 JPEG 原字节交给识别；WebP 必须转换时只编码一次，保留完整颜色精度。实际收到的尺寸和字节数可在 debug 阶段日志检查。
- CXR-L 宿主明确支持后，首次单击直接开始录音，眼镜播放短提示音，再单击结束。RGR06 左单击走普通语音／当前窗口确认，中单击快捷输入目的地，录音中中单击也结束录音。快捷标记随识别重试保留，不需要用户先说“导航到”。候选仍需要明确确认。
- 明确的“取消／取消任务／停止导航／结束任务”在取得识别文本后本地处理，不再额外调用规划模型；手机停止入口保留。
- 眼镜系统功能键点击默认关闭，可在手机显式开启，下次连接生效。移除了把系统长按当作本应用取消的映射。已识别戒指的前缀、滚动和保留键在本 Activity 内不转换为业务动作，诊断模式仍只记录输入。
- 导航提醒先进入独立播报通道；原生 TTS 与模型推理分开调度。高频导航进度进入有时效的事实存储，并由核心按顺序处理安全状态，不额外调用模型。
- 八轮反馈耗尽会清理待消费反馈并提示重述，下一轮可正常继续；导航中可搜索新目的地、播报候选、确认后才停止旧路线并启动新路线。

## 后续四项修复

- 播报队列可用更高优先级提醒抢占可中断播报，等待原生停止回执后再继续。`speech.stop → play.stop → play.stopped` 只停止对应 speechKey 的音频，不撤销录音、授权窗口或导航。停止回执有 3 秒上限，失败关闭连接；迟到的停止指令不能停止新的播报。critical 播报不被普通转弯提醒抢占，旧宿主未声明能力时保留原行为。
- 抢占同时取消云端 TTS（不取消 ASR/OCR），作废旧的预合成任务。已在执行的本地合成不能强制终止，新的首音延迟仍需真机确认；不把离线模拟当作实时性能保证。
- 新增 routeId 标识。新路线开始、旧路线停止、到达或失败时清除导航事实，保留其他观察事实；新宿主对迟到的旧 routeId 回调直接丢弃。旧宿主缺少 routeId 时仍按生命周期清理事实，但不能提供同等级的迟到回调隔离。
- 确认目的地预算从 3 秒调整为 8 秒，覆盖内部 5 秒启动导航的预算；3.1 秒返回成功的回归用例通过。
- 页面与服务统一为 fine/coarse 满足其一；通知权限独立于连接必需权限，拒绝通知后仍继续；授权回调通过后自动继续原连接操作。
