# v0.4.0 手机与眼镜真机测试交付说明

> 2026-10-20 更新：v0.4.0 权重缺少视觉编码器，图片理解存在确定故障。请安装 v0.4.1 后再按下述用例复测；新版下载和合并方法见 [视觉修复交付说明](2026-10-20-cxrl-vision-fix.md)。下文旧版 APK 链接仅作历史记录。

适用对象：负责现场测试的同学。日期：2026-10-15。

目标：确认完整 APK 在实际手机上能够离线语音对话，并完成眼镜拍照、Gemma 图片理解和眼镜显示；检查重复操作、取消和恢复。请按顺序执行，失败时保留证据，不要把“接口成功”直接填写为“实际看见 / 听见”。

## 1. 下载与准备

- [下载完整 APK：phone-l-speech-v0.4.0.apk](https://github.com/wwq031/AI-glass-for-blind/releases/download/cxrl-speech-v0.4.0/phone-l-speech-v0.4.0.apk)
- [对应发布页](https://github.com/wwq031/AI-glass-for-blind/releases/tag/cxrl-speech-v0.4.0)
- 文件大小：2,081,669,128 字节，约 2.08 GB。不是旧版 Mock 包，也不是只含 Gemma 的 v0.3.0。
- 手机：Android 12 或以上、ARM64；建议安装前至少空余 10 GB。实际 GPU 是否兼容，以本次初始化和推理测试为准。
- 准备眼镜、匹配的 Rokid 官方 App、充足电量。USB 可用于传 APK、复制证据；日常测试不需要电脑或 ADB。
- 安装 APK，若系统提示，允许本次使用的浏览器或文件管理器安装应用。可以先覆盖安装；若失败，截图保留完整系统提示，不要直接清除旧数据。
- APK 自身没有账号登录步骤。眼镜配对、连接及官方账号操作在 Rokid 官方 App 中完成。
- 使用无个人信息的物体作为拍照场景，例如杯子、书、水瓶。请在静止、安全的环境测试。

当前功能边界：录音使用**手机内置麦克风**，默认通过手机扬声器播报。眼镜麦克风、实体键触发、持续监听、导航不属于本轮功能。眼镜拍照和文字显示仍依赖官方 App；语音对话可以单独用手机测试。

## 2. 首次打开与设备记录（T01）

1. 打开安装后的“乐奇双端实验·CXR-L”应用，核对顶部版本为 `0.4.0`。
2. 保持应用前台，等待同时出现：
   - `Gemma 已就绪`。
   - `离线语音识别与播报已就绪`。
3. 首次启动会解包、校验模型并初始化，请记录从打开应用到两项就绪的实际等待时间。不要在初始化时反复退出或点击推理。
4. 如果出现失败、闪退或长时间停留在初始化，截图记录提示和已等待的时长，本项标记失败或阻塞，先反馈，不填写“就绪”。
5. 记录手机型号、Android 版本、官方 App 版本、眼镜型号与固件版本。眼镜固件版本还需要通过应用中的“记录眼镜固件版本”填写保存。

通过标准：两类模型均实际就绪，界面可操作。仅安装成功不算通过。

## 3. 手机离线播报（T02）

1. 调高手机**媒体音量**，点击“输出：手机扬声器”。
2. 点击“测试离线语音播报”。
3. 应听见类似“你好，离线中文语音播报测试。现在是二零二六年。”的完整中文声音。
4. 实际听见后，点击“人工确认听见本次播报”，再选“已听见”。
5. 记录有无无声、断字、重复、严重杂音，以及声音实际来自哪个设备。

通过标准：声音确实来自手机扬声器，内容可理解，播放结束后能进行下一项。显示“播报结束”但没有声音，应记失败，不点听见确认。

## 4. 三轮手机语音对话（T03）

每轮都按以下步骤操作：

1. 点击“开始说话（手机麦克风，最长30秒）”。首次请求麦克风权限时允许；权限返回后需要**再次点击**此按钮。
2. 在弹窗中点击“开始录音”，确认界面提示正在使用手机麦克风。
3. 靠近手机，以正常音量说完一句话。
4. 点击“结束录音并发送给 Gemma”。等待识别、回答、播报依次完成，不要连续重复点击。
5. 截图保留界面上的“识别”和“回答”，核对识别是否保留原意、回答是否相关、实际播报是否与回答一致。
6. 听完后点击“人工确认听见本次播报”→“已听见”，再开始下一轮。

建议三轮固定话术：

| 轮次 | 对手机说的话 | 核对重点 |
| --- | --- | --- |
| 1 | 你好，请用一句话介绍你自己。 | 有识别、有相关回答、有声音 |
| 2 | 请记住，我今天想买苹果和牛奶。 | 能识别两样物品并正常回应 |
| 3 | 我刚才想买哪两样东西？ | 回答应包含苹果和牛奶，检查上下文 |

三轮之间不要切后台、清空历史或导出文件，这些操作会清空当前对话历史。此模式每次最多录音 30 秒，到时会自动结束录音并进入处理，不是持续对话。录音或播报进行中不能开启新一轮。

通过标准：三轮都能完成，未串轮、重复播报或卡死；识别与回答的问题照实记录，不要求逐字完全一致。

## 5. 眼镜连接与首次图片识别（T04）

1. 先打开 Rokid 官方 App，确认眼镜真实连接，使用官方拍照功能拍一张，确认手机收到照片。
2. 回到我们的应用，点击“重新检查官方 App”。顶部“官方 App 安装”和“版本兼容”应均为 `true`。这只能证明环境检查通过，不能替代实际连接。
3. 等待模型就绪，点击“请求官方授权（不拍照）”，按官方页面完成授权。如果首次要求蓝牙 / 附近设备权限，允许后再次点击对应操作。
4. 出现用户授权成功后，点击“创建并连接 CUSTOM_VIEW Session”。
5. 等待下方日志出现连接成功和 `SDK Session Started`。此时眼镜可能显示 `CXR-PROBE #…`，这是初始探针，还不是图片理解结果。
6. 点击“测试口径：冷启动”或“测试口径：热运行”：刚重新启动手机应用的第一轮选冷启动，同一应用运行期间的后续轮选热运行。这里不代表复用同一个眼镜 Session。
7. 戴好眼镜，面向准备好的物体。点击“拍照：打开本次确认窗口”，在弹窗中点击“确认拍照”。
8. 等待手机出现当前场景照片、Gemma 推理完成及 SDK 显示更新记录。推理有 120 秒超时；出现失败或超时按实际记录，不无限等待。
9. 佩戴者核对眼镜实际显示 `Gemma：<画面描述> #<代号>`；描述应与照片主要物体一致，`#` 后代号应等于手机本次 `request=` 的前 8 位。
10. 只有实际看见对应结果后，点击“人工确认眼镜看见本次 Gemma 文本”→“已看见对应文本”。
11. 点击“朗读最近一次图片识别结果”，核对实际播报与本次图片描述一致，听完再做听见确认。

通过标准：现场照片、Gemma 描述、眼镜文字及本次请求代号对应，图片结果可以实际朗读。只看到 `CXR-PROBE`、旧结果、Mock 文本或“SDK 接受更新”，均不算本项通过。

## 6. 连续三张图片与 Session 回收（T05）

1. 第一张完成后，换一个明显不同的物体，再点“拍照：打开本次确认窗口”。
2. 应先回收旧 Session，确认 Idle，再授权 / 连接新 Session，随后弹出**新的拍照确认窗口**。如出现官方授权页，按提示完成。
3. 必须重新点击“确认拍照”，才应采集第二张图片。不需要每次手动关闭、手动创建 Session。
4. 对第二、第三张分别重复照片、描述、代号核对和眼镜可见确认。
5. 记录三次不同的 `request=`，以及是否需要手动恢复。若提示回收超时、未 Idle，截图保存后再尝试恢复。

通过标准：三次图片来自各自现场，三次请求代号不同，无旧照片 / 旧文字串入；每次拍照都有本次明确确认，正常情况下无需杀进程。

## 7. 取消、后台与恢复（T06）

按以下子项逐个做，开始下一项前等待旧任务结束。原生模型计算可能在取消后继续收尾，期间提示忙时不要反复重试。

| 子项 | 手机操作 | 预期结果 |
| --- | --- | --- |
| 取消录音 | 开始录音，说几个字，点“取消录音 / 推理 / 播报” | 停止收音，不应生成并播报这次回答；可重新开始 |
| 取消推理 | 录音后发送，在识别或回答处理中点取消 | 取消后不再播报这次旧回答；旧任务结束后能重新测试 |
| 取消播报 | 播报中点取消 | 停止当前声音，不应稍后自动续播 |
| 录音进入后台 | 录音中按 Home，稍等再回应用 | 不自动恢复录音、不播报旧回答；重新开始须再次明确确认 |
| 图片确认取消 | 打开拍照确认弹窗，点“取消” | 不采集本次照片，不产生本次图片理解结果 |
| 图片处理中进入后台 | 确认拍照后，在接收或推理中按 Home，再回应用 | 旧请求作废，不把晚到结果作为新结果；眼镜旧文字未清除本身不等于新请求成功 |
| 恢复后再拍一张 | 回应用后点“手动恢复（关闭旧连接，重新授权）”，授权成功后手动创建连接，再明确确认拍照 | 新请求可以完成，代号与旧请求不同 |

录音时可观察系统麦克风使用指示；取消后应结束本应用的收音。不要用系统录屏的麦克风指示混淆判断。

## 8. 断网与眼镜蓝牙声音（T07、T08）

### T07：断互联网复测

1. 完成正常联网测试后，关闭手机移动数据和 Wi-Fi，**保留蓝牙**，不要直接开启会关闭蓝牙的飞行模式。
2. 保持应用前台，再做一次测试播报和一次手机语音问答，核对实际文字和声音。
3. 若现场设备连接方式允许，再做一次眼镜拍照；官方 App / 眼镜链路若失败，请与手机模型离线结果分开记录。
4. 拍摄网络开关状态及操作结果。系统界面切换会触发后台取消，因此应先完成网络切换，再重新发起测试。

通过标准：手机语音识别、Gemma 回答、TTS 在断互联网后仍可运行。眼镜链路单独填写通过 / 失败 / 阻塞及原因。

### T08：眼镜蓝牙播报（有对应媒体输出设备时执行）

1. 在 Android 系统媒体输出中选择眼镜，确认媒体音量。
2. 回应用点“输出：系统媒体路由（可选眼镜蓝牙）”，再点“测试离线语音播报”。
3. 佩戴者实际确认声音是否来自眼镜，听见后再点人工确认。
4. 切回“输出：手机扬声器”再测试，核对路由可切换。

没有可选眼镜媒体设备时标记阻塞，并附系统媒体输出截图。日志显示 Bluetooth 不能证明声音一定从眼镜播放。无论选择哪种输出，本版录音仍使用手机麦克风。

## 9. 每组结束后导出记录

1. 先完成该组全部可见 / 听见人工确认，或记录失败，再点击“导出脱敏验收记录 JSON”。
2. 在系统文件选择器中选择“下载”等可找到的目录，修改文件名后保存。
3. 返回应用等待提示“脱敏记录已导出”。导出会读取约 2 GB 的 APK 计算校验值，可能需要等待，勿立刻强退。
4. 在手机文件管理器确认文件存在且不是空文件，再发送给开发同学。

重要说明：

- 导出文件选择器会使应用进入后台，取消当前任务并清空语音历史，所以不要在三轮上下文测试中途导出。
- 测试记录存于当前 Activity 内存，退出、销毁或杀进程后可能丢失。需要重启 / 冷启动前，先导出上一组。
- 建议按“语音组”“图片组”“取消恢复组”“断网及路由组”分别导出，每组尽量在同一 Activity 生命周期内完成；后一次导出可能包含前面同一生命周期的记录，交付时注明重叠，不把重复请求算新样本。
- JSON 包含请求代号、阶段时间、结果和人工确认；**不包含录音、识别文字、回答、照片**。文字和现场一致性需要截图、录像及结果表补充。
- 顶部固定提示中的“拍照、显示：未验收”不会因为人工确认自动改成通过，应以本次实际结果和证据填写表格。

## 11. 出问题时怎么处理

- **没有声音**：检查媒体音量、当前输出路由；先切手机扬声器重测，附实际状态。
- **一直是 CXR-PROBE**：截图手机图片 / 推理 / 显示更新最后几行及本次请求代号，记录佩戴者看见的文字；不要点可见确认。
- **模型失败或内存不足**：保留原始提示、手机型号和存储信息；不要通过反复重装抹去现场。
- **Session 卡住**：先记录错误，点手动恢复，授权后重新创建连接，再明确确认新拍照；仍失败则标记阻塞。
- **需要退出或重启**：先导出已有记录。闪退来不及导出的，提交发生步骤和外部录像，说明日志未保留。

全部必测项有证据后再给总体结论。失败、阻塞和未测必须区分填写；T08 无硬件媒体路由时可单独阻塞，但不能据此宣称已通过眼镜声音验收。
