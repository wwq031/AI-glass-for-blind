## 接手任务一：原生助手抢占后保住步行路线

**复现步骤。** 戴上并亮屏，使用本应用连接眼镜。对眼镜说“导航到附近某个公共地点”，确认候选，等听到路线就绪。先在本应用保持前台时短按左键、说一句问题、再短按结束，记录对照结果。然后在静止状态下触发镜腿触控板的原生助手，退出原生助手回到助盲应用，再短按左键提同一问题。分别记录能否听到回答、是否重复索要目的地，以及高德是否仍在原来的路线上。避免用手机的高德地图入口替代。

**代码能确定的原因。** 仅收到 `onAiWake` 已不会主动断开。但眼镜 Activity 的 `onPause()` 会清除按键授权并发送 `user.cancel / glasses-paused`；手机 CXR 层收到应用暂停、助手中断或会话暂停时也可能走 `fail()`。手机服务的 `retire()` 同时撤销媒体并调用 `stopWalking()`。因此一旦走进这些分支，之前的路线和对话都会被清掉。普通导航回调的排队优化无法恢复已清掉的会话。尚缺现场时间线来判断一次具体误触先走了哪个分支。

**建议修改与验收。** 单独处理暂时失焦：立即关闭麦克风与待拍授权，停止当次播报，丢弃迟到的识别、照片和模型结果，同时保留已确认启动的路线。CXR-L 1.1.2 的 `PausedReason` 可区分 `AI_ASSIST` 与 `BT_DISCONNECTED`。恢复前台后用一次真实短按开启新语音，继续原路线；恢复本身不得开麦。另测录音途中抢占、拍照等待时抢占、暂停期间到达，以及主动取消和蓝牙断开。验收时核对导航启动次数仍为 1，旧回调不会播报，真正停止后无后续路线提示。当前版本没有实现这段临时恢复。现场固件触控板长按菜单仅观察到眼镜助手、手机助手两个选择，尚未验证可彻底屏蔽原生助手的官方接口。

## 接手任务二：菜单错字与串价

**当前链路。** “读菜单”由 Agent 请求 `vision.menu`，佩戴者短按确认拍照。眼镜拍照参数是 `640 × 480`、质量 80；手机解码后又以 JPEG 质量 85 编码。图片交给 DeepSeek OCR，识别行转成 `menu.text_line`，随后由 Agent 组织答复并播报。对于返回 `pages[].text` 的结果，解析器会去除坐标框标记后按换行拆分，行置信度填 0；有文字的页面可能整体标记为部分成功。这一数值表示该分支没有取得逐行可信分数。双栏菜单上的名称和价格能否对应，需要独立验证。[OCR 解析](../../apps/phone-companion/src/android/vision-client.ts) · [菜单行转换](../../apps/gateway/src/observation/ocr-adapter.ts)

**同图对照。** 使用佩戴者提供的 1126 × 1257 双栏咖啡菜单，在 Windows 简体中文 OCR 中识别。以 13 个已人工核对的饮品名为答案，去除空白后要求完整名称出现在识别行内。全程在本机处理。

| 输入 | 完整名称命中 | 解释 |
| --- | ---: | --- |
| 原始菜单图 | 13/13 | 这张清晰原图上的名称可读 |
| 整页缩至 430 × 480 | 5/13 | 模拟竖版整页放进 480 像素高的画面，只改变取样大小 |
| 将缩图双三次插值放回原尺寸 | 10/13 | 仍漏“焦糖玛奇朵”“法芙娜热巧克力”“芋泥麻薯鲜奶” |
| 从原图按三个菜单区域人工裁切 | 13/13 | 本样本原图已全中，未观察到额外的名称增益 |

该实验只有一张清晰的电子菜单，未测反光、手抖、倾斜、价格归属、小字配料或过敏原；也未调用扫描全能王的修复模型或 APK 的 DeepSeek OCR。持有同一原图的接手人，可在带简体中文 OCR 的 Windows 上运行 `powershell -NoProfile -File tools/measure-coffee-menu-ocr.ps1 -ImagePath <原图路径>`。脚本自带答案、裁切坐标和评分规则。[实验脚本](../../tools/measure-coffee-menu-ocr.ps1)

**适合借鉴的扫描功能。** 扫描全能王官方列有高清拍摄、自动裁边、亮度和对比度调节；对模糊照片，官方优先建议调整距离、对焦、避开阴影与反光。“照片高清修复”另列为联网功能，官方推荐人脸占比较大的照片。现有数据支持先保留真实文字细节，再验证增强的收益。[扫描全能王官方 FAQ](https://www.camscanner.com/faq)

**建议的第一个实验。** 用同一张菜单、相同距离实拍，对比当前档与设备支持的更高分辨率，记录实际返回尺寸、JPEG 大小、识别耗时；对同一帧分别送原图与裁边、透视校正后的图片。保留列内的菜名和价格位置，分别统计“完整名称正确”和“同一行价格正确”。加入反光、斜拍与轻微抖动，并逐级比对眼镜帧、OCR 行和最终播报。用户听到“这部分字太小，请靠近一点，再按左键”即可重拍；看不清的价格、配料应明确告知。生成式修复补出的笔画无法作为报出价格或过敏原的依据。

## 接手任务三：定位搜索失败发生在哪一段

手机的“高德导航设置”须完成隐私授权并允许位置权限。手机模块使用高德 **Android 平台** Key；包名为 `com.leqi.experiment.phonel`，签名 SHA-1 应与实际安装包匹配。构建可通过本地环境变量 `AMAP_ANDROID_KEY_PHONEL` 提供；新手机的 DeepSeek Key 在手机设置界面录入。源码中可查看[高德配置读取顺序](../../apps/device-experiment/android/build.gradle)和[原生搜索与算路接口](../../apps/phone-companion/android/src/main/java/com/leqi/experiment/phonebt/AgentNavigationDevice.kt)。

在同一位置、同一公共地点上，依次核对语音转写、权限、定位是否成功、POI 搜索是否返回候选、语音确认是否命中候选、步行算路回调是否成功。记录各段结果和供应商错误码即可。验收覆盖定位拒绝、合法查询但没有候选、服务鉴权失败、算路失败、正常开始和用户主动结束；每种失败应给出与该阶段一致的语音提示。
