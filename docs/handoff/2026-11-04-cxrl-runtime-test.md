# 安装包实际运行测试（2026-11-04）

本轮把已有完整 APK 安装到本机 MuMu 实例 2，直接运行 Android 应用及 APK 内真实模型，不是重跑 Node 单元测试。

## 环境与测试范围

- Android 15 / API 35，模拟器支持 `x86_64,arm64-v8a,x86`，通过 `libnb.so` 运行 APK 的 ARM64 原生库；约 4GB 内存。
- 手机与眼镜 APK 均为当前 `0.5.0` 安装包；正式 APK 和正式源码未因本次运行测试改变。
- 没有 Rokid 官方 App、实体眼镜或手机；没有执行导航云服务调用。
- 临时测试程序只调用当前 APK 中的模型端口。CPU 对照测试改变的是临时测试程序传入的后端参数，正式服务仍选择 GPU。

临时测试还直接从调试 UID 启动了缺少权限的服务，复现 `FOREGROUND_SERVICE_CONNECTED_DEVICE` 前置权限不足时服务崩溃。正常 Activity 有权限预检，这不是正常按钮路径的崩溃证据；仍提示服务内部缺少独立的启动前置条件保护。补齐模拟器应用权限后，正常服务能够启动并完成模型加载。

## 发现与结论

1. 当前 GPU 选择不能在此模拟器完成真实文本/图片推理；CPU 对照通过说明权重与基本模型端口可运行，但不能据此宣称正式 GPU 软件完整通过。
2. 当前“模型已就绪”基于初始化与会话创建，尚不足以排除真正 `sendMessage` 时的后端错误。需要将实际推理可用性与初始化完成区分。
3. 模拟器的 `uiautomator dump` 自身在写出 XML 后出现原生退出码 139。崩溃进程是 `uiautomator`；应用启动结果另由应用 PID、Activity 状态与截图核对，未把测试工具崩溃误记为应用正常启动失败。
