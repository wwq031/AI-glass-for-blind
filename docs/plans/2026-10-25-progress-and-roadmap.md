## 1. 基线与目标

本次远端核对基线为 `b9cbdada9e09485df287797e152ed9c59b146822`（main，PR #39），语音版为 v0.4.2/versionCode 7。#37–#39 均已合并，当前无开放 PR；#39 分支末次提交的 CI 与 CXR-L probe 工作流成功。本次未运行构建、模型或真机测试。

本地 main 为 `ce09f5f`，工作区在新增本文前干净；另有 `agent-harness-p0` 工作区，位于 `0440d21`，也无未提交修改。本地显示的 ahead 7/behind 12 仅相对旧 origin/main 缓存 `b58c0d1`，不是相对上述最新远端的差异计数。本文依据远端源码与记录整理，不能把本地旧代码当成最新实现。没有执行 pull、merge、reset、提交或发布。

产品目标沿用仓库既有设计：盲人或低视力用户不看手机，即可表达目标、确认、观察、听取结果、追问与取消；进一步完成导航到目的地及按需入口/文字辅助。餐厅是参数化验收样例，不是写死的业务流程。

现阶段已有可运行的 CXR-L 语音/图片能力与部分现场确认。仍需补齐无屏入口、正式 Agent 接入、导航集成和可重复验收。不能将所有旧问题继续写成当前已复现故障，也不能由新 APK 的局部成功关闭全部历史问题。

## 5. 路线选择

推荐先收敛当前设备体验，再接通统一业务链路，最后扩展专长能力。备选是先做完整导航演示，或先投入 YOLO/Laya；前者容易混合尚未验证的入口与会话问题，后者会增加数据、功耗和运行调度变量。现阶段采用前一种路线。

推进依赖：S0 → S1 → S2 → S3 → S4；S5 的资料与离线样本定义可提前准备，实时接入须等待 S2/S3 的资源、授权和取消边界成立。依赖约束的是集成验收，不禁止提前做只读研究。各阶段完成后单独评审下一阶段，不按日历自动推进。

### S0：统一进度与开发基线

目标：所有人知道测的是哪一版、哪些结论仍缺证据。

1. 保存本地独有提交清单，比较最新远端与两个本地分支，不在旧 main 上直接覆盖合并。
2. 开发前确定一个最新主线工作基线和唯一写入者；需要隔离时再建立工作区。
3. 按第 4 节准备 Issue 状态更新，给每项证据标记版本、来源和范围；证据不足保持开放。
4. 建立一份验收索引，引用已有记录，不搬运未脱敏原始资料。

交付：分支处理方案、状态账目、证据索引。完成条件：实现事实与现场事实逐项可追溯，遗留问题无重复或相互矛盾的完成声明。

本文完成了账目和路线草案；分支对齐、原始资料归档和远端 Issue 更新尚未执行。

### S1：收敛 v0.4.2 的基础语音与识图体验

进入条件：确认测试 APK 身份、设备/路由以及已有 v0.4.1 记录；无需重做已确认的全部物体与三轮问答。

1. 同一手机、相同输出路由下，固定播报首次一次、热运行两次。
2. 一轮正常问答、一次已识别图片朗读，检查全句完整和段间停顿。
3. 首段播放中取消并开始新问答；再做一次切后台与返回，检查旧声音不会恢复。
4. 导出 JSON，附能辨认实际出声的短录像。分开统计首段就绪、软件播放请求、实际出声。
5. 只针对出现的失败阶段修复；若无同条件旧版数据，给出新版测量值，不计算提速百分比。

交付：小规模对比报告和失败定位。完成条件：本轮样本没有漏读/重复/旧音频残留，首段与停顿体验有明确判断。若收益不足，留在 S1 优化，不因桌面基准较快就通过。此小样本不是可靠性或 P95 验收。

### S2：建立可用的无屏入口与设备恢复

进入条件：S1 基础输出稳定；设备和官方 SDK 接入能力可核对。

1. 核对官方支持的实体键、会话类型、麦克风和音频路由，不预设 SDK 一定提供所需能力。
2. 先验证一条“触发 → 明确确认 → 拍照/问答 → 眼镜可听反馈 → 取消”的短链；首次配置可使用手机。
3. 记录物理动作到契约事件的映射及官方助手共存行为，不臆造短按/长按含义。
4. 实测后台、灭屏、断连、取消与重新授权；恢复后必须建立新请求，旧授权和旧结果不复活。

交付：设备能力与映射表、最小无屏闭环、恢复记录。完成条件：首次配置后，该短链无需手机屏幕操作；实际输入源和输出设备明确。若官方路线不支持关键入口，输出具体阻塞与候选路线，单独评审后选择，不把屏幕按钮当作已达标。

### S3：让现有 Agent Harness 统一接管任务

进入条件：S2 已有可靠设备接缝；先做当前源码接线审计，再确定最小实现范围。

1. 对照 phone-l 与现有 phone-companion：画出录音、模型调用、观察、播报、取消和会话状态的实际归属。
2. 选择复用或适配已有入口的具体方案。业务规划沿用 TS 核心，不新建并行 Kotlin 业务 Agent/FSM；录音/播放等设备状态可保留在适配层。
3. 接通用户 Event → SessionOrchestrator → 受校验 AgentPlan → ToolGateway → Provider 结果 → followUpEvents → Effect。
4. 将现有真实语音、Gemma、CXR-L 能力接到上述接口，统一播报优先级与中断处理。
5. 验证澄清、追问、任务切换、取消及过期结果拒收。能力没有接通时如实返回不可用。

交付：接线设计、最小纵向集成和对应回放/现场记录。完成条件：真实请求经过唯一业务权威，外部结果回到同一会话；授权检查与统一语音队列实际生效。只按本次改变的接缝补必要测试，不重复已有核心覆盖。

### S4：按两个切片完成导航和到达后的观察

进入条件：S3 的真实设备与 Agent 闭环可用；真实定位和地图服务条件明确。

S4-A 导航：语音目的地 → 附近候选 → 语音确认 → 真实定位/路线 → 导航事件与提醒 → 到达/取消。先核对已有适配器实际状态，不按旧文档重写。最小检查覆盖成功路径、无定位或地图失败、取消；导航播报与模型回答不能互相覆盖。完成条件是目标设备跑通这条链，不能用打印路线或假 GPS 代替。

S4-B 观察：到达提醒 → 用户确认 → 找入口；用户另行请求 → 阅读文字/菜单 → 基于同一次结果追问。采用参数化目标，沿用注册 Skill/Provider，不硬编码餐厅流程。检查低置信要求重拍、无授权不取帧、断连可解释、上下文不串任务。

交付：先两个独立切片记录，再一条完整黄金场景记录。完成条件：主流程无需看手机，导航/观察事实与授权可追溯，异常可以停止或降级。可见表情辅助作为单独可选验收项，不强绑到菜单后执行。路口辅助须单独验证事实有效期、方向和保守策略，不将本阶段描述为自主导航或通行安全保证。

### S5：评估并逐步接入 YOLO/Laya 专长能力

依据既有长期讨论稿；它仍未批准实施。当前不锁定模型版本、训练规模或设备性能阈值；选型时重新核对原始模型资料及许可，不沿用旧桌面/服务器数字。

1. 定义价值与数据：首批类别、视野方位词表、哪些可选文字判断值得交给 Laya；先建立确定性规则基线。
2. 离线评估：YOLO 输出视觉事实；Laya 输出有限枚举或弃答。按路线/会话切分留出数据，防止邻近帧或近似对话泄漏。
3. 影子运行：明确授权下只记录结果，不改变必要导航提醒；测目标手机延迟、误报/漏报、内存、温升与能耗。
4. 有限实时 YOLO 提示：只有帧源、取消和资源预算通过后才启用；提示当前视野类别和方位，不推断可靠距离或移动方向。
5. 有限 Laya 决策：中文留出评估、校准和弃答路径成立后，仅参与非强制说明/重复/升级选择；必需提醒仍由确定性策略产生。
6. 主 Agent 接管：复杂询问、冲突与弃答回到主会话，统一任务 ID、有效期、资源和事件生命周期。

交付：候选比较、设备指标、授权与生命周期设计、逐级启用决定。完成条件：相对现有基线有可测收益且不破坏取消和必需提醒；收益不足则保留规则或主 Agent，不为长期路线强行加入模型。Specialist Host 的具体设计在本阶段单独评审。

## 7. 最小验证和阶段管理

- 本轮仅文档整理：检查来源、阶段依赖、证据措辞、文件变更范围，不跑全套工程测试。
- 每次实现先复用相关测试，只补新边界；不通过删除原覆盖制造通过。
- 每个阶段评审时记录：产物、证据等级、仍缺条件、下一阶段是否进入。阶段完成不自动授权后续功能开发。
- 现场证据至少关联日期、APK/源码版本、设备与官方 App/SDK 版本、路由、请求标识、预期与实际结果；隐去设备编号、令牌和敏感媒体。
- 重复样本量按目标设置：本次 TTS 用少量定向对比；需要可靠性或 P50/P95 时再执行 #25 的独立重复验收，不让全套验收阻塞每次小修复。
