# ADR 0001：采用模块化单仓库并隔离设备传输

## 状态

已接受，作为第一阶段工程基线。

## 背景

项目同时包含眼镜 JSUI、手机伴侣、地图导航、视觉模型、Coze Agent 和 Rokid CXR 通信。CXR 手机 APK 中已经发现 `libcxr-bridge-jni.so`、`libcxr-sock-proto-jni.so` 和包含认证、请求、二进制传输、音频流及客户端管理的 Native 协议实现，但第三方应用能否直接调用、具体鉴权和消息字段仍需要验证。

## 决策

采用一个模块化单仓库：

- 领域状态机和跨端协议放在 `packages/`，不依赖任何设备或供应商 SDK。
- 眼镜端、手机端和可选网关放在 `apps/`。
- 手机—眼镜连接统一经过 `DeviceTransport` 接口。
- 先提供 `SimulatorTransport`，再接入 `RokidCxrAdapter`，未来才考虑 `DirectCxrAdapter`。
- 研究材料放在 `research/`，不把逆向产物当作生产源码。

## 结果

组员可以先用模拟适配器开发完整场景，CXR 协议未完全复现不会阻塞会话、导航和视觉模块。代价是需要维护事件合同和适配器，但可以避免把 Rokid 私有实现扩散到所有模块。

## 被否决的替代方案

- 让 Agent 直接调用 CXR、地图和摄像头：耦合高，难以测试，也无法统一安全策略。
- 把 RokidApp 进程作为业务核心：会把主动提醒、导航和模型编排绑定到官方应用生命周期。
- 现在就刷机替换系统服务：风险高，不是第一阶段纵向流程的必要条件。
