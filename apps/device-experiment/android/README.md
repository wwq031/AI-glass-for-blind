# 乐奇双端设备实验

这里的 APK 是我们自己的手机端和眼镜端连接探针。眼镜不需要单独连接 Wi-Fi。ADB 仅用于安装、启动和观察日志。

- `phone`：手机扫描眼镜 BLE 广播，读取 CXR 连接参数，建立数据通道，发送和接收带会话序号的探针事件。
- `glasses`：眼镜通过 CXR-S 订阅消息并发送探针。`leqi_debug_pairing=true` 启动参数只用于测试时让眼镜进入配对模式；正常启动不触发配对。
- `common`：版本化的会话消息编码与解码。
- `phone-l`：CXR-L 手机端探针，通过 Rokid AI App 授权并尝试取得眼镜数据服务。
- `phone-bt` / `glasses-bt`：自有 Android RFCOMM 蓝牙通道探针，不依赖 CXR-M 授权文件；双端共用 `BluetoothWire` 会话标识。

手机端 CXR-M 1.2.2 的 `connectBluetooth()` 需要 Rokid 提供的授权数据。应用从自己的私有目录读取 `cxr-license.lc` 和 `cxr-client-secret.txt`；缺少时会显示授权材料未就绪。授权文件、密钥、原始设备日志和 APK 构建输出均不提交到 Git。

## 2026-09-29 实机记录

- 荣耀手机 Android 16、Rokid `RG_glasses` Android 12：两个 debug APK 均成功构建、安装并启动。
- 眼镜 CXR-S 消息订阅返回 `0`。首次扫描时眼镜蓝牙为开启且可连接，但没有广播配对信息；手机 15 秒内未发现设备。
- 通过眼镜端 `startBTPairing(0)` 触发后，眼镜系统记录 `ble advertise start`；手机扫描到 `Glasses_4423`，GATT 服务发现和连接参数读取成功。
- 手机执行第二阶段 `connectBluetooth()` 时使用空授权材料做诊断。眼镜短暂报告手机连接，手机 SDK 返回 `SN_CHECK_FAILED`，随后眼镜断开。**双向 CXR 消息往返尚未通过。**
- 手机为诊断临时启用的“充电时保持唤醒”已恢复原值 `0`；眼镜系统在连接失败后记录 `stop advertising`。

## 替代通道实机记录

- `phone-l` 经 Rokid AI App 授权成功，`CXRLink.connect(token)` 返回 `true`；但眼镜数据服务绑定后 `binder=null`，没有连接回调或业务消息，故 CXR-L 数据通道尚未证实可用。
- `phone-bt` 和 `glasses-bt` 在这台荣耀手机与 Rokid 眼镜上建立了自有 RFCOMM 连接。21:58 手机发送 `probe.phone #1`，眼镜收到；22:09 眼镜发送 `probe.glasses #1`，手机收到。双向传输已通过。
- 22:05 用户按眼镜实体功能键，系统记录 `KEYCODE_SPRITE_FUNCTION` 和 `ACTION_SPRITE_BUTTON_UP`，首版只监听 `ACTION_SPRITE_BUTTON_CLICK`，没有发出消息。新版监听按下、抬起、单击、双击和长按；22:14 用户展开镜腿再按键，眼镜发出 `probe.glasses`，手机收到 `sprite-button-up` 和 `sprite-button-click`。实体键到手机实测通过；正式业务事件必须去重。
- 手机端加了单次真机定位探针，只有定位开启、已获权限、时间差不超过 15 秒且精度不差于 100 米才发 `location.fix`。22:21 手机发送真实定位事件，眼镜收到 `location.fix #1`；位置数值不写入诊断日志。
- 入口拍摄实验中，手机显式发送 `entrance.arm`，眼镜只在随后实体键单击时发送一次 `entrance.confirm` 并拍摄。22:29 眼镜摄像头生成 62,412 字节 JPEG，按块经蓝牙发送；手机按长度、SHA-256 和 JPEG 文件头校验后确认完整接收。图片只在两端内存中处理，诊断日志不输出图片正文。此项证明摄像与图片传输，不代表视觉模型已识别入口。
- 语音采集实验中，手机显式发送 `voice.arm`，眼镜实体键单击后采集约 3 秒 16 kHz 单声道 PCM 并封装 WAV。22:37 手机完整收到 96,044 字节 WAV；此项证明麦克风采集与上行传输，不代表模型 ASR 已识别文字。
- 语音采集实验还观察到一次实体键长按事件，该事件没有触发录音；随后一次单击才触发 `voice.confirm`。实验流程当前使用单击进行授权，正式交互仍需明确设计各按键动作。
- 手机发送测试音频到眼镜。首次眼镜播放失败，原因是静态 `AudioTrack` 在写入前处于 `STATE_NO_STATIC_DATA`，应用错误地提前判断为失败。调整为写入后检查后，22:44 眼镜记录完整写入、开始播放和播放结束。22:50 发送约 2 秒提示音，眼镜记录完整写入与播放结束，佩戴者确认从眼镜听到了声音。此项证明音频下行与扬声器可用，不代表模型 TTS 已接入。

当前已验证自有双端小消息、实体键、单次真实定位、拍摄传输、麦克风音频上传和眼镜音频播放 API。连续导航、模型 ASR/TTS、视觉模型识别与端到端任务仍未完成实机回环，不能把完整导航 Demo 标为通过。

## 当前可安装包

`dist/phone-bt-debug.apk` 安装到荣耀手机，`dist/glasses-bt-debug.apk` 安装到 Rokid 眼镜。两包已于 2026-09-29 实机安装；`dist` 是本地构建产物，不提交 Git。此实验应用的手机屏幕按钮仅用于授权和设备能力验证，不是盲人用户的最终主流程。

### 设备能力演示顺序

1. 打开眼镜“乐奇双端实验·直连眼镜”及手机“乐奇双端实验·直连手机”，在手机点“连接眼镜自有蓝牙通道”，确认显示“已连接”。
2. 点“发送真机当前位置”，眼镜记录收到 `location.fix`。位置弱或过旧时应用会拒绝发送。
3. 点“测试：准备眼镜语音采集”，佩戴眼镜单击实体键并说话约 3 秒；手机显示 WAV 完整到达。
4. 点“测试：准备入口按键拍摄”，佩戴眼镜单击实体键；手机显示入口确认及 JPEG 完整到达。
5. 点“测试：眼镜播放短音”，佩戴者可从眼镜听到约 2 秒测试音。

这些步骤是设备能力展示，仍未执行目的地语音识别、路线规划、连续导航或视觉模型判断。
